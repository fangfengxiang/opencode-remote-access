# 设计文档

**简体中文** · [English](en/design.md)

## 原生 GUI 与 IPC

窗口使用 OpenCode 原生设置组件和错误提示。错误提示可关闭，也会自动消失。各语言文案在 `src/i18n/` 中维护，交给宿主 GUI 的 `Plugin.define({ i18n })` 和 `ctx.t()`。OpenCode v2.3.0 使用 `en`、`zh`、`zht` 和 `ru` 作为插件语言键。

Electron 主进程负责文件、监听、登录日志和浏览器操作。窗口通过 IPC 查询状态和发起操作。修改 IPC 方法表或返回结构时更换 IPC 版本 ID，防止宿主热更新继续使用旧桥接对象。

## 监听、认证与配对

网关从桌面端取得本机服务地址和认证头。远程入口绑定用户选择的地址和端口，可使用 HTTP 或 TLS，内部请求继续发往 OpenCode 的本机服务。自备证书从用户指定的 PEM 路径加载。自动证书使用系统 OpenSSL 生成，按访问主机保存在插件用户数据目录下，私钥只在主进程中读入。

白名单根据实际套接字来源，在认证和配对前执行。HTTPS 连接通过 TLS 建立后统计来源和设备，白名单拒绝的请求返回 HTTP 403。已通过认证的上游请求使用桌面端提供的认证信息。

OpenCode 本机服务产生一次性配对码，网关按当前监听登记。兑换后，浏览器获得会话 Cookie，OpenCode App 获得插件签发的远程会话。HTTPS 使用 Secure Cookie 和完整的 HTTPS 配对地址。「在浏览器中打开」直接使用一次性配对地址。真实账号和密码仅通过认证流程传递。

## 配置与生效

普通设置保存在用户目录下的 `~/.opencode/remote.json`，通过串行和原子写入定稿。**保存**只写待应用设置。**保存并重启**切换远程入口。HTTPS 开关和证书设置仅应用 TLS 段，保留等待生效的监听地址和登录改动。

证书先通过格式、有效期、主机匹配和私钥匹配校验，再应用到新的监听。远程入口在切换失败时尝试恢复，回滚时复用当前监听已加载的证书材料。

## 设备和日志

浏览器使用签名的站点专用设备 Cookie。缺少 Cookie 的客户端可通过配对会话或服务端密钥派生的标识归类。型号取决于请求中的客户端提示。别名和设备密钥存在桌面插件的本地存储中。

登录日志默认保存相对文件名 `login.jsonl`，运行时从插件用户数据目录解析。自定义路径可以使用绝对路径。记录采用 JSON Lines，保留最近 500 条。停用记录保留已有内容，清空只作用于当前配置的日志。

## 平台与构建

桌面功能使用 OpenCode GUI、Electron 和 Node.js 跨平台接口。Unix 控制套接字仅用于 macOS 和 Linux 上的可选快捷命令。Windows 上使用桌面 IPC，跳过 Unix 套接字。

`node scripts/build.cjs` 将 `src/` 内的 CommonJS 模块打包到 `gui-experimental.cjs`。GitHub 安装直接加载已提交的产物。`node scripts/build.cjs --check` 校验生成文件与源码一致。

## 本地数据与会话

设置页默认遮挡密码，配置文件仍保存原值。浏览器会话最长 30 天，设备标识 Cookie 最长 180 天。监听重建后，原配对会话失效。HTTPS 网关最低使用 TLS 1.2。
